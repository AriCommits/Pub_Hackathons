# AgentTune compatibility investigation

The isolated Windows environment uses Python 3.12.13, AgentTune 1.1.3 at commit `d4db4c12d52342227c4113a70183d0f64aa2f345`, TRL 1.7.1, and the versions in `requirements-rl.lock`. It leaves the existing SFT environment unchanged. The resolved PyTorch 2.11.0 wheel reports `2.11.0+cpu`: this environment cannot run the GPU study. The constructor rejects GPU mode and unknown keyword arguments. Package versions are checked; source provenance is checked against the pinned Git commit or against an unmodified local checkout and its installed Python files. This is not a hash lock for non-Python assets or proof of Linux support.

## Verified CPU fixture

Run `python scripts/check_rl_backend.py --fixture` with the cached `CohereLabs/tiny-aya-global` tokenizer. It constructs the installed AgentTune wrapper and actual `trl.GRPOTrainer` around a random, small GPT-2 fixture. Effective settings are CPU, batch size 2, two generations, accumulation 1, beta 0, no fp16/bf16, and no external reporting. It performs no optimization. The wrapper factory is `agenttune.core.backend_factory.create_agentic_trainer(algorithm, backend="trl", **kwargs)`; `setup_data()` followed by `setup_trainer()` constructs the trainer. It separates `GRPOConfig` and `GRPOTrainer` arguments by live signature inspection and otherwise silently drops unrecognized options; the adapter rejects those options.

The custom `AgenticRolloutAdapter` supplies `prompt_ids`, `completion_ids`, sampling `logprobs`, and `env_mask`. The test drives two decisions per episode through the actual wrapper and TRL `_generate_and_score_completions`: a calculator call is executed, its observation is inserted as the same user turn used in evaluation, then `finish` terminates. Exact sampled IDs must match each prefix-preserving Tiny Aya rendering; injected observation and template-only IDs have mask zero. TRL receives a completion-sized `tool_mask`. The fake policy supplies synthetic log probabilities, and the test proves mask transport, not zero gradients or real sampling. The adapter requires real callers to supply finite, aligned sampling log probabilities. Isolation of real tool state, malformed rollouts, optimization, gradients, save/reload, and GPU capability remain later gates.

The completed run is recorded locally in `results/rl_v2/r0/backend-probe.log` and `probe-manifest.json`. The manifest records exit status, source revision and SHA-256 hashes of the log, lock and cached tokenizer. The tokenizer JSON hash was `2227ea9c52e8afb3f98bfed2679008b275f2664de69dfde174b374389eb0225d`. The no-argument probe intentionally exits nonzero because real model rollout and GPU training remain unverified. `episode_token_mask` is a rendering diagnostic; `assemble_episode_tokens` is the exact-sampled-ID mask used by the custom adapter.

## Upstream limitations and later checks

AgentTune's default `create_rollout_fn` is unsuitable as-is. In a live fake-engine probe its second decision observed the calculator result, but it made a third decision after `finish`. It inserts raw result token IDs, while generation sees a full rendered user-turn wrapper. Its fallback system prompt also changes instructions. Do not use the default loop for the primary comparison; the constructor accepts only the explicit custom adapter.

Source inspection shows the wrapper accepts a model, PEFT config, reward functions, callbacks and a custom rollout; its `train()` invokes `trainer.train(resume_from_checkpoint=...)` and then saves the model. The wrapper combines rewards. Our option validator currently rejects the wrapper-only resume parameter pending lifecycle tests. TRL with `beta=0` creates no reference model. With PEFT and nonzero beta it uses a `ref` adapter if present, otherwise disables the adapter; that is not automatically the selected SFT reference. Verify its actual identity before use. Logging, checkpoint resume, loss gradients and the reference policy have not been experimentally validated here.

Plan 9 S7 has not produced the frozen SFT baseline, so real optimization is independently blocked by the plan's cross-plan gate. No train, pilot or evaluation results are claimed here.

## Tool-reward policy and beta

The live tool-reward run loads the frozen e2 adapter at `results/sft_v2/e2/checkpoint-150` with `PeftModel.from_pretrained(..., is_trainable=True)`. It does not build a new LoRA on the base model and it does not merge the adapter into the base weights. Trainable weights are the existing `lora_` matrices on `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, and `down_proj`. The learning rate stays `5.0e-6`.

Beta stays `0.0`. In TRL 1.7.1, a nonzero beta with a PEFT model and no adapter named `ref` disables the adapter for the reference forward, so the reference would be the base Tiny Aya model rather than e2. A second full reference model does not fit beside rollouts in 16 GB. This run does not create an adapter named `ref`. Beta stays 0 so a nonzero gradient can be attributed to the tool reward rather than to a KL term. The trainer still raises if `ref_model` is not `None`. The masked child refuses the RTX 4060 UUID `5b885e12-623f-268c-f07c-ee33db379969`, and the parent shell must not keep `CUDA_VISIBLE_DEVICES`.

## Beta stays 0 for the tool-reward run

TRL 1.7.1 with a PEFT model and beta other than 0 looks for an adapter named `ref`. If that adapter is missing, the KL forward disables the adapter and uses the base Tiny Aya weights. That is not the frozen e2 policy. A second full reference model does not fit beside the rollouts in 16 GB. This plan does not create a `ref` adapter. Beta stays `0.0`, `reference_policy` stays `beta_zero`, and `reference_model_built` stays false, so a later nonzero gradient can be attributed to the tool reward rather than to a KL term. The trainable matrices are the e2 LoRA targets `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, and `down_proj` at rank 16 and alpha 32. The learning rate stays `5.0e-6`. The run still refuses to start outside the masked child and still refuses the RTX 4060 UUID `5b885e12-623f-268c-f07c-ee33db379969`.
