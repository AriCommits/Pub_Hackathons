# tooluse_v2 dataset

`python -m scripts.build_benchmark_v2 --output data/benchmarks/tooluse_v2 --seed 42` reserves a new output directory and builds a reproducible 1,200/200/200/200 train/validation/new-entity-test/stress-test dataset. Existing directories are never overwritten. A failed build leaves its diagnostics in place and must be investigated before a new output path is used. Its manifest hashes the fixture bank and each produced file, lists rejects, unique groups and depth distributions. The test axes together form the sealed 400-task final set; use validation only for model selection.

Each logical group uses a separate record and product, and the split guard checks group, entity, exact and normalized prompts, and call fingerprints. Stress prompts use held-out language families on unseen entities; they are not evidence of unseen composition generalization. Generated tasks include lookup, search, database, arithmetic, ordered use, recovery, and no-tool cases. Each question states the final answer convention. Gold results are replayed against the identified v2 fixture environment and the existing deterministic calculator and finish functions. Fixture dispatch checks the environment ID and does not mutate the historical fixture tables. Full verification against S1 is an integration gate.

The private task JSONL files include oracles and gold calls. Only `train_messages.jsonl` supplies model training messages; it contains public prompts, assistant calls and observations, without task IDs, split labels beyond the train row marker, groups, or oracle objects. The fixture file, dataset manifests, and held-out answers require controlled access. Local files alone cannot enforce a sealed split; the evaluation runner must enforce and log access. `select_probe` fixes a 100-task train-only probe; `repair_mix` limits independently verified train-group variants to 120 and at most half the mix. No validation or test failures may become training repairs. This generator leaves legacy datasets and result paths untouched.
